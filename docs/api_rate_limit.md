# S.S.T 外部 API 運用方針

## 1. 目的

外部 API の制御は、処理速度を上げるためではなく、必要なシグナルを欠損なく集めつつ無駄打ちを減らすために行います。

## 2. ソースごとの役割

### 2.1 STEAM

- 商品構造の正本
- PICS API, Steam Web API, ストアページを利用

### 2.2 ACOUSTID

- 音声波形の物理的一致を与える
- 全件一律ではなく、一次候補フォーマットへ優先実行する

### 2.3 MusicBrainz

- MBZ_RELEASE: ACOUSTID で絞れた Release の補助情報
- MBZ_SEARCH: アルバム名検索による補助候補

## 3. ACOUSTID の節約戦略

1. カバー率とメタデータ充足度が最も高いフォーマット群を一次候補とする。
2. 一次候補に対してのみ ACOUSTID を優先実行する。
3. 成功率が 50% 未満なら次点フォーマット群へ昇格する。

## 4. MusicBrainz 候補選定

- Digital Media を優先する
- Bandcamp は除外寄りに扱う
- Steam / SteamDB リンクの有無を強い加点要素とする
- MBZ_SEARCH は正ソースではなく補助候補である

## 5. レート制御の原則

- ユーザー指定の RPM / TPM / RPD を超えない
- バックオフと再試行は限定的に行う
- 同一問い合わせのキャッシュを優先する
- タイムアウトや 429 で処理全体を黙って成功扱いにしない

### 5.1 MusicBrainz のプロセス共有制御

- MusicBrainz Search、Release 詳細、Recording 詳細、および Release の Artwork 画像一覧要求は、同一 S.S.T プロセス内で共有するレートリミッターを通す。
- 要求の開始間隔は `max(1.0秒, MBZ_RATE_LIMIT_DELAY)` とする。設定値が1秒より長ければその値を使い、1秒未満なら1秒に補正する。
- 単調時計で待機時間を計算し、待機から同期HTTP要求の完了まで共有ロックを保持する。複数アルバムの並列処理でも要求開始が同時にならず、失敗した要求も次の要求間隔に含める。
- APIキャッシュのヒットは外部要求ではないため、レート制御枠を消費しない。
- 制御範囲は1つのプロセス内であり、複数の S.S.T プロセスをまたぐ共有制御は行わない。

## 6. LLM API の扱い

- LLM はあいまい時のみ呼ぶ
- ファストトラック成立時は呼ばない
- コンテキスト長や並列数は実行環境に合わせて制御する
- 出力が壊れたら review に回す
