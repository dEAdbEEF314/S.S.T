# 作業者1: 現状基線と未使用・退役コード

## 目的

リファクタリング前の挙動を固定し、未使用コード・退役コードを根拠付きで分類・削除する。推測だけでコードを消さないこと。

## 対象

- `src/sst/` 全体
- `scripts/`
- `skills/`
- `tests/`
- CLI起点 `src/sst/main.py`
- パッケージ公開面、動的import、設定名による参照

## 依存関係

最初に実施する。作業者2〜4へ、テスト基線・契約テスト分類・到達性調査結果を渡す。

## 作業内容

1. 次を実行し、結果を作業記録へ保存する。
   - `uv run pytest --collect-only -q`
   - `uv run pytest`
   - `uv run ruff check src tests scripts`
   - 利用可能な型チェックコマンド
2. Fast-Track、LLM後Archive、Review、未割当、音声警告、Preflight失敗の既存テストを分類する。足りない否定テストは、実データを使わず合成fixtureで追加する。
3. importグラフと文字列検索で、関数・クラス・モジュールの参照元を調べる。次の経路を必ず見る。
   - CLI
   - `scripts/` と `skills/`
   - テスト
   - `importlib` などの動的import
   - 環境変数名・設定名
4. `pass`、空の例外処理、互換設定を一律に削除しない。意図的な無視、入力値スキップ、未実装、退役を分類する。
5. 候補を「削除」「非推奨警告付きで保持」「運用ツールとして保持」「判断保留」に分ける。
6. 削除可能な未使用import・明確な到達不能コードだけを小さな変更単位で削除する。公開面や運用経路が不明なものは削除しない。
7. 削除内容を `CHANGE_HISTORY.md` に追記し、作業記録に参照調査の証跡を残す。

## 禁止事項

- `pass` の機械的一括置換
- 未使用と断定できない互換設定・CLIオプションの削除
- `data/`、`logs/`、`output/`、`sst-work/` の掃除
- 仕様変更を伴う整理を「清掃」として混入させること

## 成果物

- 基線テスト結果
- 契約テスト分類表またはテスト内コメントではなく、作業記録
- 到達性・参照調査表
- 削除差分
- 判断保留リスト

## 完了条件

- 変更前のテスト収集数が記録されている。
- 削除候補ごとに参照根拠がある。
- 削除前後で契約テストとCLIの終了分類が変わらない。
- 作業者2〜4が同じ基線を利用できる。
